# ADR-0008: Five dashboard languages with i18next

Status: Proposed · Date: 2026-10-31

## Context
The dashboard must support English, Hindi, Marathi, Tamil and Telugu. Translation text must live in one place.

## Decision
- `i18next` + `react-i18next`, one JSON namespace per page under `locales/{en,hi,mr,ta,te}/`. English is the source of truth. CI fails on missing or extra keys.
- ICU-style plurals; dates and numbers via `Intl` with the `en-IN`-style lakh grouping. Because some locales (for example Marathi) can default to native digits in `Intl`, money and counts are formatted with Latin digits (`-u-nu-latn`) for unambiguous amounts.
- Fonts: self-hosted Noto Sans (Latin, Devanagari, Tamil, Telugu) as WOFF2 subsets, so there is no third-party font request and CSP stays strict.
- The API sends codes and `message_key`s only. The dashboard translates them.
- Shopper-facing promotion text is merchant-authored and stored per locale (`labels: {en, hi, mr, ta, te}`), resolved from `Accept-Language` with English fallback.
- Translations are machine-drafted by me and need native-speaker review before real use.
- Layout tests check long strings (Tamil and Telugu are often longer) for overflow.

## Consequences
Real five-language support with small overhead. Translation quality is a human task, tracked as risk R7.
